## 0. 全局规则（跨功能，一次定案、处处引用）

### 0.1 审核状态机总则

八条边与补充语义以 [SRS §1.3](SRS.md) 为唯一事实源，不在此复制。拷问定案的**增量规则**：

1. **组合提交**：编辑表单「提交审核」= 服务端一个事务内先落草稿、再迁移待审（首次发布直接提交 = 创建 + 提交一个事务）。对外可见结果即待审，边集保持八条、出生边保持唯一。
2. **作者主动下线**：不加新边。「编辑即撤回」不比较内容差异，作者从编辑表单按「存草稿」即完成主动下线。
3. **理由留痕生命周期**：draft→pending 迁移时置空；驳回/下架时写入（覆盖旧值）。
4. **乐观锁守卫**：一切状态迁移接口用条件更新 `UPDATE … WHERE id=? AND status=<期望值> AND deleted=0`；affected 0 行 → 业务错误「内容状态已变更，请刷新后重试」。
5. **计数解耦**：view/like/collect/comment 四计数只随互动记录增减；撤回重审后计数延续不归零。
6. **逻辑删除不动状态机**：作者可删除自己 draft / rejected / approved / 下架 的攻略（待审不可删）；deleted=1 不可复活，只能新建新攻略（新 id）。

### 0.2 统一响应与错误约定

HTTP 状态码对齐，body 恒为 `{code, message, data}` 且 code 与 HTTP 状态码一致：

| HTTP | 场景 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数/业务校验失败（含：重复点赞、状态冲突（乐观锁守卫）、封面缺失、pending 锁定拒绝、评论为空等一切可预期的业务拒绝） |
| 401 | 未登录 / token 过期 |
| 403 | 已登录但无权限（管理端非 ADMIN；操作他人资源） |
| 404 | 不存在的资源路径（攻略详情不可见走 200+提示页或 404 均可，见 FR-ART-04；接口路由不存在 404） |
| 500 | 服务器错误 |

前端 Axios 响应拦截器分发：401 → 清登录态跳登录页；403 → toast 无权限；400 → toast message；500 → toast 服务器异常。

### 0.3 鉴权、登录流转与账号状态

- JWT 自定义拦截器 + jjwt（SRS §8 定案）：校验 Token → 解析入 ThreadLocal → 路径级角色判断（管理端校验 role=ADMIN）。
- 登录成功**按角色落地**：ADMIN → `/admin`，USER → 首页；跳登录页时记录来源路由，登录成功后**回跳**。
- 登出 = 前端清 Pinia + localStorage（无服务端会话）；token 2h 自然过期。禁用/重置密码/改密码均**不强制失效在途 token**（至多 2h 随过期失效；立即失效 = P1 Redis 黑名单）。
- 未登录点互动入口 → 跳登录页（登录后回跳原页面）。

### 0.4 图片与上传

单图 ≤5MB，格式 jpg/png/webp，本地磁盘存储（断网可演示）。封面缺失显示**占位图**（草稿未传封面与游客视角同款）；头像存原图不裁剪，前端圆形样式展示；正文配图 ≤20 张（前端拦截）。

### 0.5 分页与排序基线

默认 pageSize=10、上限 50（NFR-03）。**最热公式** = like_count + collect_count 之和 DESC，并列按 view_count DESC、再按 id DESC 破缺。评论区 create_time 正序。

- **「我的发布」列表**（FR-USER-04）：update_time DESC，并列按 id DESC 破缺。
- **个人中心三列表**（FR-USER-05）：收藏/点赞/评论各自按记录表 create_time DESC，并列按记录 id DESC 破缺（取消后再收藏/点赞生成新行，排序语义 = 最近一次行为时间）。
- **「最新」排序**（FR-ART-02 攻略列表 / FR-DST-01 聚合页 / FR-HOME-01 最新区块）：create_time DESC，并列按 id DESC 破缺。
- **目的地选项列表**（FR-ART-01 发布表单 / FR-ART-03 筛选器目的地条件）：sort ASC，并列按 id ASC 破缺。

### 0.6 前台可见性总表

| 状态 / 旗标 | 游客与注册用户（前台读路径 + 互动） | 作者（我的发布） | 管理员（后台） |
| --- | --- | --- | --- |
| 草稿 | ❌「内容不存在或不可见」 | ✅ 可见 + **预览视图**（不计浏览量） | ✅ 可见 |
| 待审 | ❌ 同上；互动拒绝（400） | ✅ 可见 + 预览；**pending 锁定**（编辑/删除/重投全拒） | ✅ 待审列表 |
| 通过 | ✅ 可见、可互动 | ✅ 可见 | ✅ 管理/审核列表 |
| 驳回 | ❌ 同上 | ✅ 可见 + 预览 + 理由留痕 | ✅ 审核历史 |
| 下架 | ❌ 同上 | ✅ 可见 + 预览 + 理由留痕 | ✅ 下架列表（可恢复） |
| 已逻辑删除 | ❌ 同上 | ❌ 不再显示 | ⚠️ 行留库；评论管理仍可溯源 |

「我的收藏 / 点赞 / 评论记录」三列表**只显示前台可见的攻略**（我的评论另加：评论本身未被删）。被下架/驳回/删除的条目直接从列表消失，不做灰显徽标。

## 1. 用户模块（前台）

### FR-USER-01 注册

- **触发条件**：游客在注册页提交用户名 + 密码。
- **流程**：① 校验用户名 3–20 字符（限中文/字母/数字/下划线）、密码 6–20；② **唯一性不区分大小写**判重（与 DB ci 排序规则一致）；③ BCrypt 入密 → 建号。失败路径：重复用户名 / 格式不符 → 400 + 业务提示；不接受角色参数（默认 USER）。
- **状态/数据变化**：user 表新增一行（role=USER，nickname=username，status=启用）。
- **验收判据**：重复用户名（含大小写变体）返回业务错误；成功注册即可登录；库内密码为 BCrypt 密文；昵称默认=用户名。

### FR-USER-02 登录

- **触发条件**：已注册用户提交用户名 + 密码。
- **流程**：① 查用户并校验账号状态；② BCrypt 比对；③ 签发 JWT（userId/role/2h）。失败路径：密码错误 → 统一提示（不区分「用户不存在/密码错」）；被禁用 → 拒绝并提示；token 过期 → 401 → 前端清态跳登录页。成功后按角色落地 + 来源路由回跳（§0.3）。
- **状态/数据变化**：无库内变化；前端 Pinia + localStorage 存 token。
- **验收判据**：正确凭证返回 token 且 ADMIN→/admin、USER→首页；从互动入口跳登录者登录后回原页；禁用账号登录被拒。

### FR-USER-03 个人信息管理

- **触发条件**：注册用户在个人中心提交修改。
- **流程**：修改昵称（1–20 字符，不唯一）、头像（≤5MB，原图存储）、简介（≤200 字符）、密码（6–20，需验旧密码）。失败路径：超长/格式错 → 400。
- **状态/数据变化**：user 表对应字段更新。**用户名终身不可改**（不提供入口）；改密码仅影响登录凭证，在途 token 不强制失效。
- **验收判据**：昵称修改后前台作者信息同步显示；改密码后旧密码登录失败、新密码成功；头像未上传时显示默认占位。

### FR-USER-04 我的发布

- **触发条件**：注册用户进入个人中心「我的发布」。
- **流程**：列表按 update_time DESC 分页，每条带五态徽标 + 驳回/下架的理由留痕（就地展示，非悬停）；页顶提供状态筛选 chip（默认全部）。操作矩阵：

| 状态 | 可用操作 |
| --- | --- |
| 草稿 | 编辑 / 提交审核 / 预览 / 删除 |
| 待审 | 仅预览（编辑、删除按钮置灰并提示 pending 锁定） |
| 通过 | 编辑（= 编辑即撤回）/ 预览 / 删除 |
| 驳回 | 编辑 / 提交审核（组合提交）/ 预览 / 删除 |
| 下架 | 编辑 / 提交审核（组合提交）/ 预览 / 删除 |

失败路径：操作他人攻略 id → 403。
- **状态/数据变化**：本页只读 + 各操作触发对应迁移（§0.1）。
- **验收判据**：五态徽标齐全；驳回/下架条目理由可见；待审条目编辑/删除被拒；操作他人攻略返回权限错误；**界面形态 = 卡片流**（封面 + 徽标 + 动作行）。
- **原型结论**：`prototypes/prototype-my-articles.html` 三变体（A 卡片流 / B 表格 / C 状态侧栏）对比后选 **A**：信息密度与前台用户气质匹配，B 更像后台，C 对五态总量小的场景偏重。状态筛选以页顶 chip 形式并入 A。

### FR-USER-05 个人中心聚合页

- **触发条件**：注册用户进入个人中心。
- **流程**：三个 Tab（我的收藏 / 点赞 / 评论记录）各自分页；列表项可跳转对应攻略详情。可见性规则见 §0.6（只显示前台可见攻略；我的评论另加评论未删）。
- **状态/数据变化**：只读。
- **验收判据**：三列表各自分页且跳转有效；收藏的攻略被下架/删除后列表中消失；自己删过的评论不出现在评论记录。

## 2. 攻略模块（前台）

### FR-ART-01 发布攻略

- **触发条件**：注册用户打开发布表单。
- **流程**：填表（WangEditor 富文本 / 封面 / 目的地 / 标签 / 天数 / 花费）→ 双动作：「存草稿」走草稿档校验、「提交审核」走提交档校验，失败就地标红 + toast 首个错误（表单为纵向单页 + 底部固定双按钮）。「提交审核」= 组合提交（§0.1）。
- **字段规则表**：

| 字段 | 提交审核 | 存草稿 |
| --- | --- | --- |
| 标题 | 必填 1–50 字符 | **必填**（草稿最小要求） |
| 目的地 | 必选 | 可空 |
| 标签 | 必选 1–3 个 | 可空 |
| 封面图 | 必传 ≤5MB jpg/png/webp | 可空（列表占位图） |
| 正文 | 必填 1–50000 字符 | 可空 |
| 正文配图 | ≤20 张（前端拦截） | 同左 |
| 行程天数 | 可选 1–365 整数 | 可空 |
| 人均花费 | 可选 0–999,999 整数（元） | 可空 |

- **状态/数据变化**：article 新建行（status=0 或组合直达 1）；**落库时 jsoup 白名单过滤 + 同趟抽出纯文本副本入 content_text 列**（方案 §7.2 article 表的增量列，搜索依赖，见 FR-ART-03）。
- **验收判据**：封面缺失时提交被拦截；草档/提档校验按表逐条生效；富文本入库已过滤 XSS。
- **原型结论**：`prototypes/prototype-publish-form.html` 三变体（A 纵向+吸底 / B 三步向导 / C 左表单右预览）对比后选 **A**：向导增加步数、实时预览开发成本高，毕设性价比低；差分校验（草稿只要标题）交互经原型验证顺手。

### FR-ART-02 攻略列表

- **触发条件**：游客/用户访问列表页（首页「热门攻略」「最新发布」区块同口径取数）。
- **流程**：分页（默认 10、上限 50）；排序切换「最新」（create_time DESC）/「最热」（最热公式，§0.5）。仅前台可见攻略（§0.6）。
- **状态/数据变化**：只读。
- **验收判据**：两种排序顺序可区分且分页稳定（并列破缺生效）；草稿/待审/驳回/下架/已删均不出现；无封面条目显示占位图。

### FR-ART-03 搜索与筛选

- **触发条件**：用户在搜索框/筛选器提交条件。
- **流程**：组合条件 = 关键词（LIKE **标题 + content_text**，不用富文本原文）+ 目的地 + 标签（**单选**）+ 花费区间（min/max 各自可空，同给时校验 min≤max）。关键词 trim 后 1–50 字符，空串 = 不作为条件；超 50 前端截断不报错。
- **状态/数据变化**：只读。
- **验收判据**：组合筛选结果同时满足全部条件；搜「span」等 HTML 词不误中正文标记（纯文本副本生效）；无结果显示空态；区间 min>max 被拦截。

### FR-ART-04 攻略详情

- **触发条件**：访问攻略详情 URL。
- **流程**：前台可见 → 渲染图文正文（输出转义）+ 作者信息 + 发布时间 + 浏览量 + 互动入口，浏览量 +1（P0 不防刷）。非前台可见 / 已删 / 不存在 → 统一提示页「内容不存在或不可见」。作者本人的非通过攻略 → 预览视图（状态横幅，不计浏览量）。未登录点互动入口 → 跳登录页（回跳）。
- **状态/数据变化**：view_count +1（仅前台读路径）。
- **验收判据**：五态 + 已删 + 不存在七种情形按 §0.6 表现；作者预览不计浏览量；游客打开通过攻略浏览量 +1。

### FR-ART-05 编辑重审

- **触发条件**：作者编辑自己的非待审攻略并保存。
- **流程**：「存草稿」→ 按当前状态走边 ④/⑤/⑧（通过态即「编辑即撤回」，不比较内容差异）；「提交审核」→ 组合提交。失败路径：待审中编辑/删除/重投 → 400（pending 锁定）；操作他人攻略 → 403；并发冲突 → 乐观锁守卫拦截。
- **状态/数据变化**：status 迁移（§0.1）；reject_reason 按生命周期置空/覆盖；content_text 随保存重抽。
- **验收判据**：编辑已通过攻略后前台立即不可见；重审通过后计数延续；待审编辑被拒；两方并发操作后到者收到「内容状态已变更，请刷新后重试」。
- **原型结论**：`prototypes/prototype-audit-statemachine.html` 的 W1–W7 七场景验证：八条边 + 组合提交 + 乐观锁守卫 + 计数解耦在真实操作序列下自洽（含并发撞车、撤回重审、理由覆盖、逻辑删复活拒绝），无不可达状态、无死锁路径。

## 3. 互动模块（前台）

统一前置：**互动对象必须前台可见**（§0.6），否则 400 业务错误。防重 = user_id + article_id 唯一索引（点赞表 / 收藏表同构）。

### FR-ACT-01 点赞 / 取消点赞

- **触发条件**：注册用户在前台可见攻略详情点「点赞」。
- **流程**：未赞 → 插 like_record + like_count +1；已赞 → 删 like_record + like_count −1。失败路径：重复点赞被唯一索引拒绝（400）；取消后可再赞。
- **状态/数据变化**：like_record 增删；like_count 同步增减。
- **验收判据**：同一用户重复点赞被拒；取消后可再赞；like_count 与记录一致；对非通过攻略互动被拒。

### FR-ACT-02 收藏 / 取消收藏

- 同 FR-ACT-01 结构（collect_record / collect_count）。验收另加：收藏后「我的收藏」出现该攻略；取消后消失。
- **验收判据**：防重同上；「我的收藏」联动正确。

### FR-ACT-03 发表一级评论

- **触发条件**：注册用户在前台可见攻略详情提交评论。
- **流程**：内容 trim 后 1–500 字符（纯空格拒绝；超 500 拒绝）；插 comment + comment_count +1。失败路径：非通过攻略评论 → 400。**不支持编辑**（写错只能删除重发）；无频控。评论不做点赞（FSR §7 偏离声明）。
- **状态/数据变化**：comment 表新增；comment_count +1。
- **验收判据**：发表后详情页刷新可见；空内容/超长被拒；评论区按 create_time 正序分页。

### FR-ACT-04 删除自己的评论

- **触发条件**：作者在自己的评论上点删除。
- **流程**：逻辑删除 comment（deleted=1）+ comment_count −1。失败路径：删他人评论 → 403。
- **状态/数据变化**：comment.deleted=1（**恒等可见评论数**：自删与后台删同规则）。
- **验收判据**：自删后前台不再显示、评论记录消失；comment_count 同步 −1；后台评论管理仍可查（治理需要）。

## 4. 目的地与首页（前台）

### FR-DST-01 目的地聚合页

- **触发条件**：访问某目的地聚合页（首页目的地入口 / 筛选器跳转）。
- **流程**：展示目的地简介与图片 + 该 destination_id 下前台可见攻略分页，支持「最新 / 最热」切换（默认最新）。
- **状态/数据变化**：只读。
- **验收判据**：聚合页列表 = 该目的地前台可见攻略的分页结果；非通过攻略不出现。

### FR-HOME-01 首页

- **触发条件**：访问 `/`。
- **流程**：四区块 + 搜索框并行渲染：轮播（启用项按 sort ASC，条数由后台控制不设前端上限；仅后台启用项）、热门攻略 **8** 条（最热公式）、最新发布 **8** 条（create_time DESC）、热门目的地 **6** 个（按前台可见攻略数 DESC，并列 id ASC）。区块均可点击进入。
- **状态/数据变化**：只读。
- **验收判据**：四区块各有数据且可点击；轮播仅显示启用项；排序与启用状态后台变更后首页同步生效。

## 5. 后台（管理端，统一校验 role=ADMIN）

### FR-BOARD-01 数据看板（基础版）

- **触发条件**：管理员进入数据看板。
- **流程**：ECharts 渲染四项指标：用户总数（全部注册用户）、攻略总数（**未删除全状态**——管道视角，五态都计）、**今日新增拆两项**（今日新增用户 / 今日新增攻略，按 create_time 当日零点起）、热门攻略 TOP10（**仅前台可见**攻略，最热公式）。看板聚合 < 2s（依赖 create_time/status 索引）。
- **状态/数据变化**：只读。
- **验收判据**：四项指标与库内数据一致（按上述口径抽测核对）；TOP10 不含下架/驳回/草稿；刷新 < 2s。

### FR-AUDIT-01 攻略审核

- **触发条件**：管理员对待审攻略执行审核，或对已通过攻略执行治理。
- **流程**：待审列表 → 查看内容 → 通过（边②）/ 驳回（边③，理由必填）；已通过 → 下架（边⑥，原因必填）；下架 → 恢复上架（边⑦）。失败路径：状态期望不符 → 乐观锁守卫 400；理由为空 → 400。
- **状态/数据变化**：status 迁移 + reject_reason 写入（覆盖旧值）；通过/恢复后前台立即可见，下架后立即不可见。
- **验收判据**：状态迁移与 SRS §1.3 边集完全一致；驳回/下架理由必填；恢复上架后前台立即可见；并发下架撞上作者撤回时后到者被拒。
- **原型结论**：`prototypes/prototype-audit-statemachine.html`（W5 并发冲突、W6 下架恢复·理由生命周期场景）验证通过。

### FR-ADMIN-USER-01 用户管理

- **触发条件**：管理员在用户管理页操作。
- **流程**：列表查询；禁用/启用；重置密码（**固定默认密码 123456**，操作反馈明示）；角色分配（管理员仅由此产生）。**自保护**：禁止对自身执行禁用/启用/角色变更（改自己密码允许，走个人中心）。**存量内容保持**：禁用用户后其前台可见攻略保持可见（内容下线只走下架）。失败路径：对自身操作 → 400。
- **状态/数据变化**：user.status / password / role 更新；在途 token 至多 2h 随过期失效。
- **验收判据**：禁用后登录被拒但已签发 token 至多 2h 有效；重置后可用 123456 登录；对自身禁用/降级被拒；被禁用用户的通过攻略前台仍可见；初始数据预置一个 admin 账号。

### FR-ADMIN-COMMENT-01 评论管理

- **触发条件**：管理员在评论管理页操作。
- **流程**：评论列表（可定位所属攻略，含已逻辑删除攻略的溯源）→ 删除违规评论（逻辑删 + comment_count −1，**恒等可见评论数**）。
- **状态/数据变化**：comment.deleted=1；comment_count −1。
- **验收判据**：删除后前台立即不可见；comment_count 同步；列表能定位所属攻略（攻略已删时标注）。

### FR-ADMIN-DST-01 目的地管理

- **触发条件**：管理员维护目的地。
- **流程**：增删改查 + 图片上传（§0.4 规则）。失败路径：**删除保护**——目的地下存在未删除攻略 → 禁止删除，提示先处理。
- **状态/数据变化**：destination 增改；删除受保护拦截。
- **验收判据**：新增后前台聚合页与发布表单选项同步出现；有攻略的目的地删除被拒；空目的地可删。

### FR-ADMIN-TAG-01 标签管理

- **触发条件**：管理员维护标签体系。
- **流程**：增、改、逻辑删。删除后表单选项与攻略详情展示不再出现该标签（历史关联行留库不清理）。
- **验收判据**：新增后发布表单可选；逻辑删后表单与详情均不出现。

### FR-ADMIN-CAR-01 轮播图管理

- **触发条件**：管理员维护首页轮播。
- **流程**：增删改、排序（sort）、启用状态。**link = 后台动作的可执行对象选择器**：类型（攻略/目的地）+ 对象二选一，不做自由文本外链。失败路径：非选择器形态的 link → 表单不允许提交。
- **状态/数据变化**：carousel 增改。
- **验收判据**：排序与启用状态变更后首页轮播同步生效；点击轮播跳转所选攻略/目的地。
