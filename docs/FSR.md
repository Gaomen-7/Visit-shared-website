## 2. 项目定位（指针）

UGC 旅游攻略分享社区：三角色（游客 / 注册用户 / 管理员），前台 + 后台共用一套 REST API，JWT 区分权限。

- 角色与前后台边界：方案文档 §二
- 技术架构与关键设计（JWT 流程、跨域、分层）：方案文档 §六
- 数据库与接口设计：方案文档 §七、§八

## 3. 技术可行性

### 3.1 选型判定

技术栈按方案文档 §6.1 执行（Spring Boot 2.7.x / MyBatis-Plus 3.5.x / MySQL 8.0 / JWT ｜ Vue3 + Vite + TS + Pinia + Element Plus）。判定：全部为主流稳定组件，无实验性技术，资料与社区支持充足，技术路线成立。

### 3.2 开发环境现状（2026-10-29 本机实测）

| 组件 | 本机现状 | 项目需要 | 判定 | 处置 |
| --- | --- | --- | --- | --- |
| JDK | 18.0.2 | 17 LTS | ⚠️ | 安装 Temurin JDK 17（与 18 共存）；Spring Boot 维持 2.7.x |
| Maven | 3.6.0 | ≥ 3.6.3 | ⚠️ | 项目自带 mvnw wrapper，不动全局 Maven |
| MySQL | 5.6.23（EOL） | 8.0 + utf8mb4 | ❌ | 安装 MySQL 8.0 社区版（5.6 保留共存） |
| Node / npm | 24.21 / 11.19 | ≥ 16 | ✅ | 无需处理 |
| Redis | 3.2.100（Win 版） | 仅 P1 使用 | ✅ | 基本操作够用；砍掉不影响闭环 |
| Git | 2.56 | — | ✅ | 无需处理 |

两项待装软件均为免费、约 30 分钟量级操作，列入 §10 前提清单。**2026-10-29 已全部落地（JDK 17 / MySQL 8.0 / mvnw 均装 F 盘自建目录 `F:\dev-tools`），完成情况见 §10；安装位置、端口、账号等细节见 [DEV-ENVIRONMENT.md](DEV-ENVIRONMENT.md)。**

### 3.3 学习曲线（开发者画像：课内学过 Java Web / 数据库 / 前端，未完整做过前后端分离项目）

| 集中风险点 | 消化安排 | 解除信号 |

| Vue3 组合式 API + Pinia 工程化 | 第 1–3 周边设计边用官方文档 + Element Plus 练手 | 第 3 周末能独立写出列表 / 详情页 |

## 7. 范围可行性（防烂尾边界）

| 层 | 内容 | 规则 |
| --- | --- | --- |
| **P0 承诺范围** | 方案文档 §三 / §四表中全部「核心必做」项 + 先审后发五态审核状态机 | 必须全部完成，缺一即闭环不成立 |
| **P1 条件增强** | 轻量数据分析模块（方案 §十一）、标签推荐「猜你喜欢」、Redis 热点缓存、二级评论（楼中楼）、行程结构化（第 N 天） | 第 11–12 周时间盒内实施；CP2 不通过则全弃；每项可独立砍 |
| **P2 明确排除** | 支付 / 门票酒店预订、小程序端、Elasticsearch、关注流、举报处理、系统设置 / 公告 | 不进入排期；进入前必须先修订本节 |

P2 排除理由：支付预订涉及交易状态机且与「分享」主题弱（方案 §1.3 同判断）；小程序为多端工作量翻倍；ES 引入新组件，MySQL LIKE + 论文对比分析已够（方案 §九亮点 4）；关注流 / 举报 / 系统设置的治理叙事已由审核状态机覆盖，边际收益低。

**对方案文档的偏离声明**：方案中「关注作者 / 举报 / 系统设置」标注为加分选做，本报告将其移入 P2 排除——以本报告为准。方案 §3.3「攻略与评论均可点赞」中的评论点赞，经 SRS 问询定案砍除（点赞对象 = 攻略；方案 §7.2 点赞表与 §8.2 点赞接口设计不变）——点赞互动规则以 [SRS.md](SRS.md) 为准（2026-10-29 定案）。

**范围可行性结论：✅ 可行（边界成文）**
